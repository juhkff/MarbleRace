# 角色呈现与领跑音乐系统

> 状态：需求基线；核心代码已实现并做过无真实音频素材的 PIE 验证，具体进度见[实施计划与交接](<实施计划与交接.md>)。  
> 关联：[原视频玩法分析与制作参考 v1.1](<原视频玩法分析与制作参考.md>)。  
> 来源：用户明确补充——参考视频基于 Marble Race Simple，角色头像、姓名、BGM 等为后期剪辑；某个角色对应的球冲到第一时，切换该角色的音乐。本项目要实时完成这些工作。

## 1. 目标与范围

**游戏运行时直接生成“角色弹珠比赛成片的内容”，无需录制后逐球跟踪、贴头像、打姓名或人工切换 BGM。**

明确需求：
- 每颗参赛球绑定角色头像、姓名和主题音乐。
- 头像与姓名实时跟随对应球；沿用扁平二维视觉。
- 某角色成为当前领先者时，自动播放该角色的主题音乐。
- 呈现由比赛事件驱动，不使用提前编好的视频时间轴。

建议配套：角色资料配置、当前领跑者提示、音乐交叉淡化、缺资源回退、可调切歌策略。

范围边界：
- 本功能负责实时画面与声音；用外部录屏即可记录。不等同于已实现游戏内 MP4 编码、自动导出或剪辑器。
- 初版在编辑器内配置导入的资源；打包后运行时任意导入图片／音乐是独立扩展需求。
- 不承诺从参考视频自动提取各角色的完整音乐。用户需提供自有／获授权素材；可先用占位资源验证逻辑。

## 2. 必须区分的三个对象

| 对象 | 含义 | 是否直接决定 BGM |
|---|---|---|
| 当前领跑者 | 比赛过程中有效路线进度最靠前的选手 | 是，经过切歌稳定规则后 |
| 冠军 | 第一个有效越过终点的选手，名次锁定 | 取决于冠军后音乐策略 |
| 镜头关注者 | 观众当前看谁，可由自动镜头或手动选择决定 | 默认否 |

“冲到第一”暂按**途中成为领跑者**理解，而不只指第一个完赛。没有有效领先优势的起跑堆叠阶段应播放开场音乐，不随便按 Actor 遍历顺序挑一个角色唱歌。

镜头切到落后者时，不应自动把落后者误判为领跑者；如以后需要“音乐跟随镜头”，应做独立模式。

## 3. 角色配置：一次配置，全程一致

建议使用 UE `PrimaryDataAsset` 或 Data Asset 保存 `CharacterProfile`：

| 字段 | 用途 |
|---|---|
| CharacterId | 稳定的角色 ID，不用姓名作唯一键 |
| DisplayName | 界面显示名，可重复 |
| Portrait | 头像纹理，未设置时显示默认头像 |
| ThemeMusic | 主题曲资源，未设置时播放默认比赛曲 |
| MusicStartOffset | 首次播放起点，可直接从适合比赛的片段开始 |
| MusicGain | 曲目音量修正，减少不同素材响度差异 |
| TrailColor | 可选：角色识别色与尾迹颜色 |
| ReentryPolicy | 再次领跑时从指定起点重播，或恢复上次进度 |

每个参赛实例还有独立 `RacerId`。同一角色参与多次或同时出现多个实例时，成绩不混淆；多个实例使用同一首曲目时，领先实例切换也不必重启同一首音乐。

**所有呈现从同一配置读取**，不要分别在球、UI 和音乐播放器里维护三份手工姓名映射。

## 4. 头像与姓名的实时呈现

### 头像
- 保留平面约束的物理碰撞体作为运动主体。
- 使用独立、面向镜头的圆形头像显示层；材质无光照、不投影。
- 物理球自转不强迫头像倒转：初版建议头像保持正立，可配置是否随球转动。
- 头像显示层不额外参与物理碰撞，避免双重碰撞。
- 用圆形遮罩与轻量描边保证浅色头像在浅蓝背景中可辨认。

### 姓名
- 使用屏幕空间标签，或统一 UI 将球的位置投影到屏幕。
- 标签绑定 `RacerId`，不能根据“最近的球”猜归属。
- 姓名尽量保持可读字号，不随着相机拉远缩成不可辨认的小字。
- 数十人混战时，优先显示关注者和领跑组；其他标签可淡化。这是可选可读性优化。
- 球离开视野后隐藏标签，不能让标签滞留在屏幕边缘误导观众。

## 5. 领先判定：不是谁的 Z 最低谁第一

参考赛道含折返、反弹、旋转和并排分支。仅按高度排序会把暂时掉低、走错通道或被弹回的球误判为领先。

建议进度模型：
1. 按正确路线设置有序赛段／必经检查点。
2. 每段用路径参数、局部检查点或专用进度函数衡量当前位置。
3. 将分支映射到共享的入口—出口进度区间；不能因两条路长度不同而随意比较局部距离。
4. 先比较已经合法通过的阶段，再比较当前阶段的进度。
5. 非法穿墙、掉出赛道、未满足前置检查点的球不获得领先资格。

需要明确：
- 已通过检查点的记录可以保留；当前段内进度应允许倒退，否则被弹回的人会虚占领先。
- 若允许逆向跨段，需要单独定义规则；初版宜让阶段边界不可逆，段内允许反弹。
- 对圆形闭环、分支等歧义区域，可暂时保留现有领跑者，直到检查点确认，而不是输出高频不可靠判断。
- 正式冲线名次以终点事件锁定，不由音乐稳定规则决定。

### 防止碎片式切歌（建议初值，需试听调整）

- 新候选人持续领先约 **0.5 秒**，再确认音乐目标。
- 已经播放的音乐通常至少持续 **2 秒**；冠军事件可覆盖此限制。
- 并列或极小进度差时保留当前目标；设置可调进度优势阈值。
- 比赛真实排名可以立即更新；仅音乐呈现延迟，不篡改成绩。
- 超越事件密集时只保留最新有效候选，不按队列把过时主题曲依次播放。

以上参数属于建议，不是用户已经指定的硬性时长。

## 6. 音乐导演的事件流程

```text
比赛开始 → 播放开场／默认比赛曲
    ↓
进度系统更新 → 得到领跑候选人
    ↓
持续领先与防抖检查 → 确认音乐目标
    ↓
读取该角色主题曲 → 资源就绪后交叉淡化
    ↓
领先者未变：继续播放，不重复重启
    ↓
新领先者成立：再次切换
```

UE 实现建议：
- 单独建立音乐管理器，使用两个 `AudioComponent` 交替播放，调用淡入／淡出。
- BGM 使用非空间化播放，不附着到球上；不能因球远离摄像机而听不见。
- 统一音乐音量控制，音效另分通道。
- 可用软资源引用；赛前准备或候选人出现时异步预加载，避免切歌卡顿。
- 新曲未就绪前维持旧曲，不先静音；失败时回退默认曲。
- 异步加载完成时重新核对当前目标／请求序号，丢弃已经过时的加载结果。
- 淡化期间再次换人，要取消过时过渡，维持受控声部数；不能每次事件都创建一个永久播放的音频组件。

### 再次领跑时如何播放

提供两种可配置策略：
- **从配置起点重播（建议初版）**：每次出场都有熟悉的角色片段，容易感知。
- **恢复上次位置**：降低重复感，但需要管理播放游标、循环和音频寻址支持。

曲目播完后建议循环，至少不能变成无限静音。精确循环区间属于后续可扩展项。

## 7. 冠军产生后的处理：需要用户选定

用户目前明确的是“领先角色决定音乐”；冠军产生后是否继续跟随未完赛者还未指定。

| 策略 | 行为 | 特点 |
|---|---|---|
| A：冠军主题锁定 | 首名冲线后切换并保持冠军主题，直到结果阶段 | 荣誉感强，但剩余比赛可能很长 |
| B：冠军庆祝后继续领跑音乐（建议） | 冠军主题播一段庆祝，然后跟随当前最靠前的未完赛者 | 适合继续观看剩余选手；冠军名次仍锁定 |
| C：直接跟随未完赛领跑者 | 冠军产生后立即切换至下一位未完赛者 | 连续性强，但冠军音乐可能过短 |

选择 B 时，庆祝时长可先试 5 秒；庆祝结束重新查询未完赛者进度，不能播放五秒前的过时目标。

注意：“未完赛领跑者”是剩余选手中的最靠前者，**不能在 UI 上把它写成已获第一名**。

## 8. 生命周期与异常处理

- **暂停**：比赛时钟、候选确认计时和音乐一起暂停；恢复时继续当前曲，不重头播放。
- **重开**：清空领先候选、音乐过渡、播放游标与角色实例关系，停止旧声部。
- **全员完赛**：进入结果音乐策略，不再监听竞速切歌。
- **无有效参赛者**：保持默认音乐，不取空数组中的第一项。
- **同曲换人**：可以更新领跑者姓名，但不重复启动同一音频。
- **素材缺失**：默认头像、默认姓名显示规则、默认音乐；不影响比赛继续。
- **淘汰／失效**：若后续引入淘汰规则，失效选手立即从候选集合移除。
- **手动看人**：默认只改变镜头，不改变音乐；显示当前领跑者可避免观众误会。

## 9. 最小验证版本与验收用例

先用三个角色 A／B／C、三张占位头像和三段可区分的测试音乐验证，不必等待完整长赛道。

| 测试 | 预期 |
|---|---|
| A 首次形成稳定领先 | 播放 A 的曲目，头像与姓名匹配 |
| B 超越并持续领先 | 无人工操作淡化到 B 的曲目 |
| A/B 短时间交替领先 | 不发生每帧切歌或多曲叠播；最终目标正确 |
| 领先者一直不变 | 曲目持续播放，不每次更新进度就重头开始 |
| B 再次领跑 | 遵循重播／续播配置 |
| 摄像机关注 C，但 B 仍领先 | 仍播放 B 的曲目 |
| B 无主题曲 | 使用默认曲，无崩溃和长时间静音 |
| 新曲加载中候选又变了 | 过时曲目不突然播放 |
| 两个实例共享同一角色／曲目 | 名次仍按实例区分，音乐不无意义重启 |
| 第一个选手完赛 | 正式冠军锁定；音乐遵循选择的冠军后策略 |
| 暂停再恢复、整场重开 | 无残留音轨、错位姓名或旧候选事件 |
| 直接录制运行窗口及游戏音频 | 录制结果已有头像、姓名和自动切换 BGM，无需后期添加 |

## 10. 制作优先级

1. 角色配置资产与球实例绑定。
2. 头像圆形显示、姓名跟随。
3. 简单赛道的路线进度与领跑事件。
4. 音乐导演、默认曲回退、双声部淡化。
5. 防抖、冠军后策略、暂停重开测试。
6. 接入完整复杂赛道，验证折返与分支的进度判定。
7. 数十人压力测试、标签拥挤处理与素材配置体验。

**这属于核心功能，不应等整张地图复刻完才追加。**
