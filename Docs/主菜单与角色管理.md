# 主菜单、角色管理与开局滚筒

> 版本：v1.0（2026-09-27）  
> 来源：用户明确提出的新需求。  
> 关联：[实施计划与交接](<实施计划与交接.md>)、[角色呈现与领跑音乐系统](<角色呈现与领跑音乐系统.md>)、[原视频玩法分析](<原视频玩法分析与制作参考.md>)。  
> 本文是玩法与界面规格，也是实现约定；实现进度以[实施计划与交接](<实施计划与交接.md>)第 10 节为准。

## 1. 用户原话与拆解

> “游戏开始时，会先在主菜单，主菜单有开始游戏，角色设置，退出。点击开始游戏时，就会进入现在的页面自动进行游戏；点击角色设置时，会进入管理小球的页面，显示现在的小球，可以创建新的小球，角色可以给每个小球设置显示的图片（传入图片）、领先时播放的BGM。游戏开始时，每个小球的位置不再固定，而是像视频中显示的那样，将所有小球都放在一个类似滚筒的机关中，机关不断旋转，确保每个小球在倒计时结束时所处的位置随机。”

拆成四件事：

1. **主菜单**：开始游戏／角色设置／退出。
2. **角色设置页**：列出当前小球；新建小球；为每个小球设置头像图片与领先时播放的主题曲。
3. **开局滚筒**：所有小球不再固定摆放，而是装进一个持续旋转的滚筒，倒计时结束时位置随机。
4. **流程串联**：主菜单 → 开始游戏 → 直接进入现有赛道自动比赛。

### 已确认的实现选择（用户 2026-09-27 当面选定）

| 事项 | 选择 | 理由 |
|---|---|---|
| 菜单技术 | **C++ 画布菜单**（沿用现有 HUD 体系） | 不需要美术资源即可运行；与现有角色层同一套绘制代码；以后要换 UMG 不影响数据层 |
| 主题曲来源 | **只能从工程里已导入的音频资源中选择** | UE 运行时不能解析 mp3/wav；这是引擎限制，不是偷懒 |
| 菜单位置 | **独立主菜单关卡** | 结构清晰；`Content/Maps/MainMenu` 与赛道 `NewMap` 分开，开始游戏时用 `OpenLevel` 进入赛道 |

## 2. 流程与状态

```text
启动游戏
   │
   ▼
MainMenu 关卡（AMarbleRaceMenuGameMode + AMarbleRaceMenuHUD）
   ├── 开始游戏 ──► OpenLevel(NewMap)
   ├── 角色设置 ──► 同一 HUD 切到设置页（不换关卡）
   └── 退出 ─────► 打包版结束进程；PIE 里结束当前 PIE 会话
                        │
                        ▼
              NewMap 关卡（AMarbleRaceGameMode + AMarbleRaceDirector）
                        │
   读取角色名单 ─► 生成/收集小球 ─► 全部投入滚筒 ─► 滚筒旋转(=倒计时)
                        │
                   倒计时结束 ─► 打开滚筒释放小球 ─► Racing ─► Results
```

赛道关卡的 `Ready → Countdown → Racing → Results` 状态机保持不变，只是 **Countdown 阶段同时就是滚筒旋转阶段**，倒计时结束的那一刻释放小球。

## 3. 角色名单：数据与持久化

角色不再是纯编辑器资产，而是**游戏内可增删改的名单**，因此存到存档里：

- `FRaceCharacterEntry`（USTRUCT，SaveGame）：
  - `FString DisplayName`：显示名，可中文。
  - `FLinearColor Color`：识别色，同时用于圆盘、姓名配色与尾迹。
  - `TArray<uint8> PortraitPngData`：头像原始图片字节，**存进存档**，因此换机器也还在。
  - `FString PortraitSourcePath`：导入时的原始路径，仅作显示与重新导入用。
  - `TSoftObjectPtr<USoundBase> ThemeMusic`：主题曲，软引用指向工程内已导入资源。
- `URaceRosterSave : USaveGame`：`TArray<FRaceCharacterEntry> Entries` + `int32 Version`。
- `UMarbleRaceRosterSubsystem : UGameInstanceSubsystem`：**GameInstance 级**，因此跨关卡存活。
  - `GetEntries()` / `AddEntry()` / `RemoveEntry(int32)` / `MoveEntry()`
  - `SetDisplayName()` / `SetColor()` / `SetPortraitFromFile(const FString& Path)` / `SetThemeMusic(int32, USoundBase*)`
  - `SaveRoster()` / `LoadRoster()` / `EnsureDefaults()`
  - `UTexture2D* GetPortraitTexture(int32 Index)`：按需从字节创建并缓存。
- 存档槽：`Saved/SaveGames/MarbleRaceRoster.sav`。

**首次运行**：如果存档不存在，生成 6 个默认小球（不同颜色、英文名 + 占位名），保证一进游戏就能跑。

**与 `URaceCharacterProfile` 的关系**：`URaceCharacterProfile` 继续作为**单场比赛中每个球的运行时身份容器**（头像、姓名、颜色、主题曲），由导演在开赛时用名单条目构造临时实例。赛道 HUD 与音乐组件不需要知道名单的存在，现有接口不变。

## 4. 界面规格

### 4.1 主菜单页

| 元素 | 行为 |
|---|---|
| 标题 | `弹珠竞速` |
| 开始游戏 | `UGameplayStatics::OpenLevel("NewMap")` |
| 角色设置 | 切到设置页 |
| 退出 | 打包版 `QuitGame`；编辑器 PIE 下结束 PIE |

### 4.2 角色设置页

| 区域 | 内容 |
|---|---|
| 左侧：小球列表 | 每一行显示：色块 + 头像缩略图 + 名称 + 主题曲名。点击选中 |
| 右侧：选中项设置 | 名称（点击后键盘输入，支持中文 IME）／颜色（预设色板循环）／图片（列表选择或输入路径）／主题曲（列出工程内全部 `USoundBase`，点击选择） |
| 底部按钮 | `新建小球`、`删除选中`、`上移`、`下移`、`返回` |
| 提示行 | 显示「主题曲需先在编辑器导入」等限制说明 |

**图片导入的两条路**（都支持）：

1. **文件夹选择（推荐）**：把图片放进 `Saved/Portraits/`，菜单自动列出 `*.png *.jpg *.jpeg *.bmp`，点击即用。
2. **输入路径**：文本框中输入或粘贴绝对路径（兼容中文路径）。

导入后立刻把图片字节存进名单条目并刷新缩略图；原始路径一并保留。

**主题曲选择**：用 `AssetRegistry` 枚举工程内所有 `USoundBase`（含 `USoundWave`、`SoundCue`、MetaSound），列出名称与所在路径，点击选择。列表过长时支持翻页。

**输入**：鼠标点击为主；名称与路径用文本框。文本输入通过 `FSlateApplication::Get().OnKeyChar()` 接收字符，因此中文输入法可直接用。

## 5. 开局滚筒

目标：倒计时结束时**每个小球的位置随机**，观感接近原视频开局的旋转滚筒。

`ARaceStartDrum`（新 Actor）：

| 属性 | 说明 |
|---|---|
| `Radius` | 滚筒内半径 |
| `WallHeight` / `WallSegments` | 圆周墙体（用 `/Engine/BasicShapes/Cube` 拼），分段数即拼装块数 |
| `BladeCount` | 内部径向搅拌叶片，把球带着转，避免所有球贴着同一侧 |
| `SpinSpeedDegrees` | 旋转角速度（度/秒） |
| `SpinAxis` | 默认绕 Y 轴（本作物理平面是 XZ，Y 为侧向） |
| `FloorThickness` | 底盘，释放时关闭碰撞让球落下去 |
| `DrumMaterial` | 外观材质，保持项目扁平黑色风格 |

接口：

- `void BeginSpin(float SpeedDegrees)`
- `void ReleaseDrum()`：停止旋转 + 关闭底盘碰撞 + 打开释放口，球在重力作用下离开滚筒
- `void ResetDrum()`：恢复底盘碰撞、清空角速度，供重开使用
- `void PlaceRacer(AActor*, int32 Index, int32 Total)`：把第 Index 个球放到滚筒内一个初始角度上（等分摆放，避免初始重叠）

**随机性来源**：球在旋转筒内真实碰撞、被叶片带动、互相挤压，倒计时结束时的位置由物理决定。物理是确定性的，但**位置不再固定**，符合用户要求。若以后要更强的随机性，可给初始角度加随机扰动（已预留属性）。

**导演侧改动**：

- 新属性：`bUseStartDrum`、`StartDrumClass`、`StartDrumLocation`、`bSpawnDrumIfMissing`。
- 开赛流程：收集全部参赛球（关卡内 `RaceMarble` 标签的球 + 按名单补足生成的新球）→ 逐个 `PlaceRacer` 放进滚筒 → `BeginSpin` → 倒计时期间保持旋转 → 倒计时归零时 `ReleaseDrum` 并进入 Racing。
- 重开（`RestartRace`）：`ResetDrum` → 重新摆球 → 重新旋转 → 重新倒计时。
- 关卡里已放置 `ARaceStartDrum` 时优先使用，不再自动生成第二个。

**小球数量**：以名单条目数为准。关卡里已有的球也参与比赛（打上 `RaceMarble` 标签即可），数量不足时按模板补生成，数量多余时按占位身份处理。

## 6. 与既有系统的边界

- 领跑判定、音乐防抖、冠军策略、正式名次**完全不受影响**，它们只认 `RacerId` 与进度。
- 名单只负责“有哪些球、长什么样、唱什么”，不参与比赛逻辑。
- 现有赛道、材质、由用户编辑的关卡内容一律不重建、不删除；关卡里那颗球继续参赛。
- 缺图片 → 彩色圆盘 + 姓名首字；缺主题曲 → 默认曲；都没有 → 静音。这条回退链保持不变。

## 7. 明确的限制

1. **主题曲必须预先导入工程**：运行时只能从已导入的 `USoundBase` 里挑，不能直接读 mp3/wav。
2. **头像可以运行时导入**：从磁盘读取图片文件，字节存进存档。
3. 名单存在本地存档，不进版本库；要换机器需拷贝 `Saved/SaveGames/`。
4. 画布菜单是即时模式 UI，没有动画与过渡效果；换成 UMG 是后续可选项。
5. 独立主菜单关卡与默认启动关卡需要写入项目配置（`DefaultEngine.ini` 的 `GameDefaultMap`），改完需重启编辑器或重新打开项目才生效。

## 8. 验收用例

| 编号 | 用例 | 预期 |
|---|---|---|
| M1 | 启动游戏 | 先看到主菜单，而不是直接开始比赛 |
| M2 | 点击开始游戏 | 进入赛道关卡，小球全部出现在滚筒内 |
| M3 | 倒计时期间 | 滚筒持续旋转，小球被带动、位置不断变化 |
| M4 | 倒计时结束 | 小球从滚筒释放并下落，各自位置互不相同 |
| M5 | 同一场比赛重开 | 重新回到滚筒旋转阶段，位置与上一局不同 |
| M6 | 进入角色设置 | 列出当前全部小球及其颜色／头像／主题曲 |
| M7 | 新建小球 | 列表新增一条，默认名与颜色，返回后可参与比赛 |
| M8 | 选择头像图片 | 缩略图更新；比赛中该球的圆盘显示这张图 |
| M9 | 选择主题曲 | 该球成为领跑者时播放所选曲目（需已导入音频） |
| M10 | 删除小球 | 列表中移除，下一场比赛不再出现 |
| M11 | 退出 | 打包版退出进程；PIE 下结束会话 |
| M12 | 重启游戏 | 名单仍然保留（存档生效） |

## 9. 不做的事

- 不做联网、账号、云存档。
- 不做运行时音频解码。
- 不做 UMG 界面与动画。
- 不改动用户现有赛道几何与材质。
- 不因为引入滚筒而删除关卡里已有的球或机关。
