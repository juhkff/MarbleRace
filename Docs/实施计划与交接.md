## 1. 用户真正要的功能（不可偏移）

用户说明：原视频是 **Marble Race Simple 的游戏画面 + 后期添加的角色头像、姓名、BGM 等**。当某角色对应的球冲到第一时，切换该角色的音乐。

本项目应在运行时直接实现：
- 每颗球绑定角色头像、姓名和主题曲。
- 头像、姓名随球实时显示，不依赖录制后的逐帧跟踪。
- **途中领跑者变化驱动主题音乐变化**，不是只有冠军冲线时才播放。
- 直接录屏就有角色呈现和自动音乐，不需要再后期贴图、打名字或手动切 BGM。
- 球依靠物理与机关比赛，不恢复 WASD 默认玩家球。
- 保留用户要求的平面侧视、纵向赛道、无球面光泽和投影的扁平外观。

### 新增需求（2026-09-27 用户提出）

在原需求之上增加一整套“游戏外壳”，详见[主菜单与角色管理](<主菜单与角色管理.md>)：

- **主菜单**：开始游戏／角色设置／退出，独立关卡 `Content/Maps/MainMenu`。
- **角色设置页**：列出、创建、删除小球，并为每个小球设置头像图片与领先主题曲。
- **开局滚筒**：所有小球不再固定摆放，而是装进持续旋转的滚筒，倒计时结束时位置随机。
- 已确认选择：菜单用 C++ 画布实现；主题曲只能从工程内已导入资源中选择（UE 运行时不能解析 mp3/wav）；主菜单做成独立关卡。

### 此阶段不做

- 不由程序生成或重排整条赛道。零件放在内容浏览器「赛道组件」里，由用户自己在关卡中摆放。
- 不继续重建整张视频地图，也不删除／替换现有关卡来迁就代码。
- 不实现联网、下注、技能、完整传送系统、视频编码导出器。
- 不自动下载或声称拥有角色头像／商业歌曲使用权。
- 不承诺打包后导入任意磁盘音频；首版资源在 UE 编辑器中导入和配置。
- 不自动 commit、push、改凭据或强推。用户需另外明确要求。

## 2. 初版实施约定与待确认项

以下默认值是为推进实现而选择的建议，**不声称用户已逐项确认**。用户未另行要求时按此实现，并在编辑器暴露配置。

| 事项 | 初版约定 |
|---|---|
| 冠军后音乐 | 默认冠军主题庆祝 5 秒，再跟随尚未完赛的领跑者；提供锁定冠军主题选项 |
| 新领跑者确认 | 持续领先 0.5 秒，且超过可配置的小进度差阈值 |
| 最短播曲时间 | 默认 2 秒，由音乐组件管理；冠军／结算等强制事件可跳过 |
| 曲目过渡 | 双声部交叉淡化，默认 0.6 秒 |
| 再次领跑 | 从该角色配置的起点重播；续播留作后续扩展，不做假实现 |
| 同曲换人 | 姓名／领先者可变，但同一音频不重新启动 |
| 缺头像 | 显示角色颜色的圆形占位图 |
| 缺主题曲 | 使用默认比赛曲；默认曲也没有则安全静音，并清楚提示未配置 |
| 头像方向 | 显示保持正立、朝向摄像机，不随物理球翻转 |
| 音乐跟随谁 | 默认只跟随比赛领跑者，**与镜头目标解耦** |
| 音频加载 | 角色配置持有硬引用，赛前加载；首版切歌时不触发异步资源加载 |

用户素材尚未提供。可以用明确标记的自制测试图／测试音验证，不得把测试音说成角色真实主题曲。

| `Tests/Race*.cpp`（计划新增） | 进度、名次、音乐请求规则的自动化测试 | 不只测试永远返回 true 的占位用例 |

### 3.1 已创建的角色配置接口（不要重复创建另一套）

`URaceCharacterProfile : UPrimaryDataAsset`：
- `FName CharacterId`
- `FText DisplayName`
- `TObjectPtr<UTexture2D> Portrait`
- `FLinearColor Color`
- `TObjectPtr<USoundBase> ThemeMusic`
- `float MusicStartOffset = 0`
- `float MusicGain = 1`

角色 ID 与参赛实例 ID 不同。两颗球可以使用同一角色配置，但成绩必须使用独立 `RacerId`，不能靠显示名作键。

### 3.2 已约定的音乐组件接口

```cpp
void RequestTheme(USoundBase* Sound, float StartOffset = 0.f,
                  float Gain = 1.f, bool bForce = false);
void ResetMusic();
void SetMusicPaused(bool bPaused);
```

属性：`DefaultMusic`、`CrossfadeSeconds = 0.6`、`MinimumPlaySeconds = 2`。

- 输入为已加载资源；空曲目使用默认曲。
- 音乐组件只保留**最新**待播目标，不排一长串已经失去领先的角色。
- 比赛导演负责 0.5 秒领跑防抖；音乐组件负责 2 秒最短播放时间，避免两处各自再加一层同类计时。
- 强制冠军事件可跳过最短播放时间，但不能打破显式暂停。
- 同曲目重复请求不得重新 `Play()`。
- 两个持久非空间化音频组件，任意时候最多两个声部；快速变化必须复用／停止旧声部。
- 曲目自然结束按配置起点重播；音源本身循环也可。重开、销毁时停止全部声部。

### 3.3 计划中的导演对外接口（名字可以局部修正，职责不可漂移）

- `RestartRace()`：清理状态、恢复起点、进入倒计时。
- `SetRacePaused(bool)`：同时控制世界／比赛与音乐暂停。
- `GetLeader()`：真实有效的当前领跑者，不是音乐当前播放者。
- `GetCameraTarget()`：默认优先跟随未完赛领跑者；不可倒过来影响 BGM。
- 只读参赛者／成绩列表供 HUD 使用。
- `OnLeaderChanged`、`OnRacerFinished` 等事件可蓝图绑定。

所有状态由导演单点维护；禁止 GameMode、HUD、音频组件各自维护不一致的排名。

## 4. 比赛与进度规则

### 状态机

`Ready → Countdown → Racing → Results`，暂停为附加状态。初版支持重开，不要求改用另一张地图才能重赛。

### 参赛者接入

1. 优先使用关卡已放置的 `AMarbleRaceDirector`，禁止自动创建第二个导演。
2. 如果没有导演，GameMode 创建一个运行时默认导演，以兼容现有地图。
3. 已带 `RaceMarble` 标签的 Actor 可自动注册／附加参赛者组件；不得要求用户删掉现有球重新建关卡。
4. 导演提供角色配置数组、是否生成测试球、测试球数量等选项。
5. 当前只有一个球。为验证反超可在运行时生成少量测试球，使用稳定的 A/B/C 占位身份；不保存到编辑器地图，也不破坏用户原始球。
6. 保存每个参赛者初始 Transform；重开恢复并清空线速度／角速度、历史位置、检查点与名次。

### 正式路线模式

- 按唯一顺序号排列检查点，终点必须是末项。
- 检查点局部 `Z=0` 为穿越平面，前进方向为局部 `+Z → -Z`；横向范围由 BoxExtent 限定。
- 使用上一位置到当前位置的线段与平面求交，减少高速球漏触发；只接受下一个合法检查点。
- 使用交点插值比例估算该物理步内通过时刻。
- 同一更新周期所有终点事件按通过时刻排序，完全相同则使用稳定实例 ID，而不是 Actor 枚举顺序。
- 检查点可以附一条本段入口到检查点的样条，用最近路径参数表示本段进度。
- 先比较合法通过的阶段，再比较当前阶段的局部进度。阶段内进度允许倒退。
- 初版按不可逆阶段边界设计；分支、闭环和允许跨阶段倒退的地图必须额外标定，不能声称任意地图自动识别路线。
- 重复顺序号、缺少终点或错误序列需要明确日志／拒绝正式开赛，不默默给错误排名。

### 当前地图兼容模式

现有关卡是简单竖直下降，没有检查点。可提供显式标记的 `VerticalFallback`：用起点到可配置终点高度归一化计算进度。

**这只是旧地图兼容方案，不是完整路线算法。**必须在 HUD／日志或说明中标明；复杂路线应放置正式检查点。

注意现有黑白格在底部平台下方，物理球可能先被平台挡住。兼容终点需配置为可穿越的高度；不能把“碰不到的黑白条下方”当作唯一触发位置，也不能为此擅自删除平台。

### 完赛与冠军后

- 第一次有效过线才记录 `FinishRank`、`FinishTime`；再次穿过不重复计分。
- 正式成绩永远不被音乐防抖延迟。
- 冠军产生后强制请求冠军主题，庆祝计时用游戏时间。
- 默认庆祝 5 秒后重新查询未完赛领先者，不能使用五秒前缓存的过时角色。
- 全员完赛时进入 Results；没有未完赛者不访问空数组。
- 初版无正式淘汰／救援系统；出界球应至少显示异常并避免虚占领先，不能偷偷传送再声称正常完赛。

## 5. 渲染与 UI 路线

为避免必须先手工制作大量 Widget／材质资产，首版优先使用 C++ HUD：

- 物理球仍由现有碰撞体驱动；头像以世界位置投影至屏幕绘制。
- 通过圆形三角扇及 UV 绘制头像纹理，避免把球上贴图渲染成受光球面。
- 半径从球世界半径投影得到，不凭空固定成与物理尺寸不匹配的圆。
- 使用白色／角色色默认圆盘与描边，缺头像也能运行。
- 显示层无碰撞、不投影、不受灯光影响；HUD 显示启用时隐藏原始球网格的视觉，但保留物理模拟。
- 姓名随球投影，画面外不残留标签。标签绑定实例 ID，不按距离寻找最近球。
- 初版可以没有完整尾迹系统；尾迹不是本次实现头像／姓名／音乐的阻塞前置任务，不得为了尾迹拖延闭环。
- HUD 至少有倒计时、素材缺失提示、领跑者、当前音乐目标、完赛结果及重开／暂停提示，方便验证二者是否一致。

以后如转为 UMG／世界空间组件，必须保留角色绑定与不受光规则，不得同时显示两套头像。

## 7. 必须覆盖的验收测试

| 编号 | 场景 | 必须结果 |
|---|---|---|
| T01 | A/B/C 各有不同资料 | 姓名、头像、曲目来自同一配置，无串绑 |
| T02 | A 领先，B 稳定反超 | 正确产生 B 领先；音乐随后切到 B |
| T03 | A/B 短时交换、并列 | 不每帧切歌；最终稳定者胜出 |
| T04 | 领先者不变 | 不重复从头播放 |
| T05 | 快速 C→A→B 请求 | 最新目标生效，最多两声部，没有旧曲排队播放 |
| T06 | 不同角色配置同一首曲 | 更新身份但不重启同曲 |
| T07 | B 没有曲／头像 | 默认资源回退；两者都缺时安全占位／静音，并有提示 |
| T08 | 镜头看 C，B 仍领跑 | 仍播放 B 的曲目 |
| T09 | 多人同帧冲线、重复过线 | 稳定唯一排名与用时，没有重复成绩 |
| T10 | 冠军冲线后仍有人在赛道 | 冠军名次锁定，庆祝后按配置跟随未完赛者 |
| T11 | 全员完赛／无球 | 正确进入结果／安全空状态，不崩溃 |
| T12 | 暂停、恢复、重开、退出 PIE | 游戏与音乐同步暂停，无旧声部、旧候选和旧成绩 |
| T13 | 球反弹回上方、穿过错误门 | 不因历史最低高度永久霸榜，不跳过必经检查点 |
| T14 | 当前简单地图无检查点 | 兼容模式可运行且明确说明限制 |
| T15 | 直接录屏观察 | 头像姓名实时跟球，音频自动变化，无需后期添加 |

验证分层：

### 本轮关键排错记录（2026-09-27 夜）

- **滚筒在 PIE 里消失**：生成出来的网格组件被标了 `RF_Transient`，而 PIE 是复制关卡世界的，复制时**跳过 transient 组件**，于是放在关卡里的滚筒到了 PIE 里既没有可见网格也没有碰撞。修复：不再标 transient，并在 `BeginPlay` 里无条件 `RebuildGeometry()`。

### 同色尾迹（用户提出，已按参考视频改为渐细飘带）

视频里每颗球都有各自颜色的尾迹，形态是：**靠近球最宽、向后逐渐收尖、半透明、长度只有约 2–3 个球直径**。实现方式：HUD 在屏幕空间按角色颜色绘制**渐变飘带**，不使用粒子或贴图资源。

- 每移动 `TrailSampleDistance`（默认 5 单位）记录一个世界坐标采样点；同时按三种预算裁剪历史：`TrailLifetimeSeconds`（默认 0.5 秒，静止后自动消失）、`TrailLengthInRadii`（默认 6 倍球半径，即 3 个球直径，保证高速时尾巴也不拖长）、`TrailMaxSamples`（默认 32）。
- 飘带用 `FCanvasTriangleItem` + 画布自带白色贴图绘制：每个顶点单独带颜色和 alpha，配 `SE_BLEND_Translucent`，因此靠近球处半透明、向尾部透明直至收成尖点，形状由 `TrailTaperPower`（默认 1.5）控制。
- 头部半宽 = 屏幕球半径 × `TrailWidthScale`（默认 0.7，比球略窄）；头部 alpha = `TrailMaxAlpha`（默认 0.45）。
- 每个采样点用相邻两段的平均切向求法线，转弯处飘带连续不裂口；采样点跑到摄像机后方时整段丢弃，不会横穿屏幕。
- 颜色直接取 `URaceCharacterProfile::Color`，与头像圆盘同色；配置真实角色后每球自动不同色。`bShowTrails=false` 可关闭。

调参过程（保留作为经验）：先用 `DrawLine` 逐段画粗线，用户反馈「太明显、哗众取宠」，于是只剩 2:1 的粗细变化，做不到视频里的收尖。改成飘带后，用**运行时夸张值**（`TrailLengthInRadii=40`、alpha 1.0）先证明几何确实渲染，再逐步调回 6 倍半径 / alpha 0.45 定稿。

验证证据：`Saved/Screenshots/ribbon-diag-2.png`（夸张参数，证明宽头细尾几何正确）、`ribbon-final-2.png`（定稿参数，开局高速下坠时的红色飘带）。历史对比：`trail-6-tuned-b.png`、`final-2.png` 是用户认为过于显眼的宽色带版本。**本轮全部为 Live Coding 热重载 + PIE 截图验证，尚未在关闭编辑器后做完整构建／打包验证。**

### HUD 文字清晰度（已修复）

原因：`AHUD::DrawText` 默认使用 `GEngine->GetMediumFont()`（约 10 px 的字形图集，`BaseEngine.ini` 里 `MediumFontName` 也被注释掉，走的是运行时兜底字体）。倒计时用 `Scale=6`、球内首字用 `Scale=ScreenRadius/8` 放大这个 10 px 图集，等于把位图拉伸 6 倍，中文必然发糊；球下姓名与顶部读数则直接就是 10 px，白字压浅蓝底更难读。

修复：全部 HUD 文字改为 `FCanvasTextItem` + `GetLegacySlateFontInfo()` 改写 `Size`，让运行时字体缓存**按目标字号生成字形**，不再放大位图。

## 11. 使用说明（已实现部分）

### 运行现有地图

1. 打开 `Content/Maps/NewMap`，按 Play。GameMode 会自动使用关卡中的 `比赛导演`；若关卡里没有导演，会在运行时自动创建一个。
2. 现有地图没有检查点，导演会打印警告并使用**高度兼容模式**：按起点到 `FallbackFinishZ` 的高度判断进度与完赛。这只适用于竖直下降地图。
3. 快捷键：`P` 暂停／继续，`R` 重新开始。两者由 HUD 轮询输入实现，无需额外配置。
4. HUD 默认隐藏弹珠网格并改画身份圆盘（`bHideRacerMeshes`），这样头像不会被球面遮挡。
5. 球外围默认没有任何边框：`MarbleRaceHUD.bShowStatusRings` 默认 `false`。若打开，白色=领跑者、绿色=音乐目标、金色=冠军。头像素材存在时仍会画一圈角色色细边框，用于让方形头像看起来是圆的。
6. 倒计时字号在 `MarbleRaceHUD.CountdownFontSize`（默认 120）；调试读数用 `bShowDebugReadout` 开关。
7. 尾迹与头像同色，参数在 `MarbleRaceHUD` 的 `Race|HUD|Trail` 分组里：`bShowTrails`、`TrailMaxSamples`、`TrailSampleDistance`、`TrailLengthInRadii`、`TrailLifetimeSeconds`、`TrailMaxAlpha`、`TrailWidthScale`、`TrailTaperPower`。想更接近参考视频就保持默认；觉得太长就调小 `TrailLengthInRadii`，太淡就调大 `TrailMaxAlpha`。运行时生成的两个测试球带 `RaceMarble` 标签并命名为 `测试球_1/2`，方便在 PIE 大纲里找到。

### 配置真实角色（头像 + 姓名 + 主题曲）

1. 在内容浏览器创建数据资产：右键 → 杂项 → 数据资产 → 选择 `RaceCharacterProfile`。
2. 填写 `CharacterId`、`DisplayName`、`Portrait`（建议圆形带透明通道的 PNG）、`Color`、`ThemeMusic`、`MusicStartOffset`、`MusicGain`。
3. 把这些资产按顺序加入 `比赛导演` 的 `AutoAssignProfiles`；注册顺序决定谁拿到哪一份。`AutoAssignProfiles` 为空时会使用占位身份。
4. 头像与姓名、主题曲来自同一份资产，不会串角色。缺少头像时显示角色颜色圆盘与姓名首字；缺少主题曲时回退 `MusicDirector.DefaultMusic`，都没有则安全静音。

### 摆赛道零件

内容浏览器文件夹 `/Game/赛道组件`。拖进关卡即可。这些蓝图已经保存，还没有在关卡里摆过，也没有 PIE。

- 斜面、陡斜面、平台、导流板、挡墙、圆钉是静态网格。导流板默认向一侧倾斜，镜像一块就能拼漏斗。圆钉直径约 36，比弹珠小。
- 弹性板、往复挡杆、上下挡杆、旋转拨板是「赛道机关」。颜色、尺寸、幅度、周期、转速都在细节面板里。
- 终点门已经勾选「是终点」，顺序默认 100。关卡里每道门的顺序要唯一，终点必须是最大的那个。
- 「旋转圆弧」和「圆底」已在「赛道组件」里。圆弧默认缺口朝下并缓慢旋转；圆底不转，开口朝上。不要热重载这个类。

### 使用正式检查点路线

1. 在关卡中放置若干 `RaceCheckpoint`：每个设置唯一 `Order`，只把顺序号最大的那个勾选 `bIsFinish`。
2. 门平面是 Actor 的局部 Z=0，通过方向为局部 +Z → -Z（默认朝向即向下坠落方向）；`HalfExtent` 是本段通路的横向范围。
3. 需要更准确的段内进度时，给该检查点的 `RouteSpline` 编辑样条；不编辑则在该段内按上一门到本门的直线估算。
4. 顺序号重复、终点数量不为 1、或终点不是最大顺序号时，导演会拒绝开赛并给出明确错误日志，不会产生错误名次。

### 音乐事件规则（已实现）

- 途中领跑者需要持续领先 `LeaderConfirmSeconds`（默认 0.5 秒）且超出 `LeaderProgressMargin` 才会切换。
- 音乐组件保证最短播放 `MinimumPlaySeconds`（默认 2 秒）与 0.6 秒交叉淡化；同一首曲不会重复重启。
- 冠军冲线会强制切到冠军主题，`ChampionCelebrationSeconds`（默认 5 秒）后跟随未完赛领跑者；`bKeepChampionThemeAfterCelebration` 可改为一直保留冠军主题。
- 正式名次由终点事件锁定，音乐防抖不会延迟成绩。
